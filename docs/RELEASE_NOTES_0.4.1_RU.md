# Примечания к выпуску MCTGAuth 0.4.1

[English version](RELEASE_NOTES_0.4.1.md)

## Основные изменения

- Полный backend на Java 21, MCTGAuth Server и MCTGAuth Client для Minecraft 1.21.1 / NeoForge 21.1.244.
- Русский и английский Telegram UI: меню, регистрация, обращения о проблемах/нарушениях, дополнительные аккаунты, переписка, модерация, поиск, включение/отключение аккаунтов, смена пароля и аудит.
- Защищённый от повторов протокол V1 с клиентским Argon2id и HMAC-SHA256, привязанным к nonce и контексту.
- Исходящий авторизованный опрос backend, атомарный JSON-кэш, идемпотентная синхронизация, ограничения до авторизации и вход по кэшу при недоступности backend.
- Debian toolkit с проверкой архивов, online backup SQLite, атомарной активацией, health check, автоматическим откатом приложения, отдельным restore БД, retention-очисткой и журналом операций.

## Backend и Telegram

- `/menu` всегда открывает обычное личное меню пользователя; `/adm` открывает административное меню; `/cancel` очищает активный workflow.
- Модератор авторизуется по числовому Telegram ID. Chat ID общей группы определяет только контекст отображения.
- Состояние аккаунта использует единственный `minecraft_accounts.enabled`; изменения транзакционны и идемпотентны, создают `ACCOUNT_DISABLED` / `ACCOUNT_ENABLED` и записываются в аудит.
- В Telegram время показывается в `Europe/Moscow`; хранение и TTL остаются в UTC.
- `/health` и `/version` возвращают безопасные сведения о версии/схеме. Sync и remote-command API требуют bearer token.

## MCTGAuth Server

- Хранит верификаторы и обработанные ID событий/команд в `mctgauth/accounts.json` с временным файлом, `.bak` и атомарной заменой.
- Применяет `ACCOUNT_CREATED`, `CREDENTIAL_CHANGED`, `ACCOUNT_ENABLED`, `ACCOUNT_DISABLED` и `ACCOUNT_REMOVED`.
- Может отключить онлайн-игрока после `ACCOUNT_DISABLED`, если `disconnectPlayerWhenAccountDisabled=true`.
- Предоставляет операторам уровня 2 команды `/mcauth status`, `/mcauth sync` и `/mcauth player <name>`.

## MCTGAuth Client

- Добавляет вход в настройки на главном экране и через меню Mods.
- Хранит выданный Telegram пароль открытым текстом в `.minecraft/config/mctgauth-client.json` согласно явному продуктовому решению. Защищайте компьютер и не передавайте этот файл.
- Позволяет изменить/очистить пароль, показать его и включить автоматическую авторизацию.
- Терминальные ошибки не запускают автоматический цикл переподключения.

## Конфигурация и миграция

- Backend получает настройки из переменных окружения процесса. `TELEGRAM_BOT_USERNAME` обязателен и указывается без `@`.
- `AUTH_API_TOKEN` должен иметь не менее 32 символов и совпадать с секретом выделенного сервера.
- Серверный секрет хранится только в закрытом `config/mctgauth-server.toml` или `MCTGAUTH_API_TOKEN`; его нельзя распространять через AutoModPack.
- Миграция `V004__telegram_workflow_fixes.sql` применяется автоматически и повышает максимальную схему до 4. Она разрешает неизвестный ник нарушителя и добавляет постоянное временное состояние ответа модератора.
- Ручное преобразование БД не требуется. Перед обновлением создайте backup SQLite штатным toolkit.

## Обновление

1. Прочитайте [инструкцию по развёртыванию](deployment/DEPLOYMENT_RU.md) и создайте backup БД.
2. Добавьте новые обязательные переменные, особенно `TELEGRAM_BOT_USERNAME`, не заменяя существующие секреты.
3. Соберите `auth-backend-0.4.1.tar.gz`, `mctgauth-server-0.4.1.jar` и `mctgauth-client-0.4.1.jar`.
4. Активируйте backend через `update.sh`; не копируйте вручную файлы SQLite/WAL.
5. При остановленном Minecraft замените оба mod JAR, затем проверьте `/health`, `/mcauth status`, синхронизацию и тестовый вход.

## Известные ограничения

- `/mcauth resync <name>`, `/mcauth reload` и выполнение типизированного `RESYNC_PLAYER` пока не работают.
- Backend привязывается только к loopback; для production TLS нужен reverse proxy.
- Release проверен автоматической сборкой и unit-тестами, но оператор должен выполнить live smoke test Telegram и dedicated server в своём окружении.
