# MCTGAuth Backend 0.6.6

[English](RELEASE_NOTES_BACKEND_0.6.6.md)

## Совместимость

| Компонент | Поддерживаемая версия |
| --- | --- |
| Backend | 0.6.6 |
| Клиентский мод | 0.6.5 |
| Серверный мод | 0.6.5 |
| Протокол авторизации | 2 |
| Схема БД backend | 8 |
| Формат отпечатка | 1 |

Этот backend-only выпуск не требует замены Minecraft-модов 0.6.5. Он устанавливается после полного обновления всего стека до 0.6.5. Клиент и сервер 0.6.4 не поддерживаются: в них нет протокола 2 и отпечатков устройств.

## Telegram UI

- Пользовательские меню, настройки, аккаунт и время игры, Server Information, мастера регистрации/обращений, Back, подтверждения и страницы используют одно активное сообщение на числовой Telegram ID и чат.
- `/adm` хранит независимое активное сообщение для каждого модератора и чата. Пользовательская и административная сессии не заменяют друг друга.
- Списки обращений, поиск, статистика, аккаунты и экраны устройств/блокировок/исключений используют ту же административную проекцию.
- Восстанавливаемая ошибка редактирования создаёт ровно одно новое сообщение. `message is not modified` считается успешным no-op.
- Callback навигации привязан к числовому Telegram ID владельца сообщения; каждое изменение по-прежнему проверяет актуальное состояние БД.
- Успешно обработанный временный ввод модератора удаляется, если Telegram разрешает; ошибка удаления не отменяет операцию.

## Постоянные и секретные сообщения

Созданные и изменённые пароли всегда отправляются отдельным HTML-сообщением без навигационной клавиатуры. Его ID не попадает в UI-сессию и не перезаписывается навигацией.

Уведомления о регистрации/обращениях, ответы, закрытие и отклонение остаются отдельными. История и модерация сохраняются в SQLite; Telegram-сообщения являются только проекциями.

## Неизменённые границы

Нет миграции V009, изменения протокола, формата отпечатка, авторизации или Minecraft-модулей. Поведение при недоступности backend и политика устройств/банов 0.6.5 не изменены.
