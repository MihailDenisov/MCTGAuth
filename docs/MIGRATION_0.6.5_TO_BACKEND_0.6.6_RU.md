# Двухэтапное обновление: 0.6.4 -> Backend 0.6.6

[English](MIGRATION_0.6.5_TO_BACKEND_0.6.6.md)

Поддерживаемый путь намеренно состоит из двух этапов:

```text
MCTGAuth 0.6.4
│
│ Полное обновление: backend + client + server
│ Протокол 1 -> 2; схема 7 -> 8
▼
MCTGAuth 0.6.5
│
│ Только backend; client/server остаются 0.6.5
│ Протокол остаётся 2; схема остаётся 8
▼
Backend 0.6.6 + Client 0.6.5 + Server 0.6.5
```

Нельзя устанавливать backend 0.6.6, оставляя в работе Minecraft-моды 0.6.4.

## Этап A: полное обновление 0.6.4 -> 0.6.5

Следуйте [существующей инструкции 0.6.5](MIGRATION_0.6.4_TO_0.6.5_RU.md). Создайте backup БД, задайте новый внешний `DEVICE_FINGERPRINT_SECRET`, примените V008/схему 8, замените клиентский и серверный моды и backend, затем проверьте согласованную авторизацию протокола 2 и определение устройства. Сохраните описанные настройки отпечатков и выполните проверки после обновления.

Откат этапа A не является простой заменой бинарного файла: изменились протокол, схема и состояние устройств. Используйте политику backup/rollback из инструкции 0.6.5 и не запускайте код 0.6.4 на схеме 8 без описанной проверки совместимости или процедуры восстановления БД.

## Этап B: только backend 0.6.5 -> 0.6.6

1. Убедитесь, что backend, client и server 0.6.5 работают с протоколом 2.
2. Создайте и проверьте online-backup БД backend.
3. Убедитесь, что последняя запись `schema_migrations` имеет версию 8.
4. Убедитесь, что JAR клиента и сервера имеют версию 0.6.5; не заменяйте их на этом этапе.
5. Подготовьте `auth-backend-0.6.6.tar.gz`.
6. Сохраните все production-настройки и секреты 0.6.5, включая `DEVICE_FINGERPRINT_SECRET`.
7. Используйте штатный update-скрипт для остановки, активации, запуска и health-check backend.
8. Проверьте `/health`, `/menu`, `/adm`, Back, страницы, выдачу пароля и экраны устройств/банов.
9. Проверьте авторизацию client 0.6.5 -> server 0.6.5 -> protocol 2 -> backend 0.6.6.

На этапе B не требуется миграция БД или новый параметр конфигурации.

## Откат этапа B

Остановите backend, верните проверенный artifact backend 0.6.5 штатным rollback-инструментом, сохраните совместимую БД схемы 8 и моды 0.6.5, запустите сервис и проверьте health, Telegram и Minecraft-авторизацию. Восстановление БД является отдельной операцией и не требуется только для отката UI-кода 0.6.6.
