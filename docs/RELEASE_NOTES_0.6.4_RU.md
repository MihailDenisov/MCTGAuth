# MCTGAuth 0.6.4

[English version](RELEASE_NOTES_0.6.4.md)

## Теги участников Telegram

- В разделе **Настройки → Тег чата** пользователь явно выбирает один включённый Minecraft-профиль, принадлежащий ему, либо **Без тега**. По умолчанию тег отсутствует; backend не выбирает профиль автоматически.
- В настройке хранится `users.chat_tag_account_id`, а не произвольный текст. Каждый callback повторно проверяет владельца и состояние аккаунта, а текст тега берётся из актуального ника авторитетного аккаунта.
- Теги применяются только в явно заданном `memberTags.chatId`. Telegram username, личные чаты, группа модераторов и произвольная активность в группах не определяют целевой чат.
- Администраторы и владельцы Telegram-чата не получают игровые теги. Статус модератора MCTGAuth не связан с ролью в чате: модератор, являющийся обычным участником целевого чата, может выбрать тег.
- Пользователь вне чата может сохранить настройку. Временная ошибка Telegram API также не откатывает уже записанную настройку. Бот повторяет попытку при получении обновления членства в целевом чате, а уполномоченный администратор может выполнить **Синхронизировать теги чата** для сверки всех настроек.
- Результат сверки содержит счётчики `processed`, `updated`, `cleared`, `skippedAdministrators`, `notMembers` и `failed`. Недействительный выбор сбрасывается, но не заменяется другим аккаунтом.

Для тегов требуется Telegram Bot API 9.5 или новее. Бот должен быть администратором целевой группы/супергруппы и иметь право `can_manage_tags`. Настройте один числовой ID чата:

```yaml
memberTags:
  enabled: true
  chatId: <TELEGRAM_GROUP_CHAT_ID>
  excludeChatAdministrators: true
```

При включённой функции `chatId` обязателен. Некорректная конфигурация безопасно отключает функцию и создаёт понятное предупреждение при запуске. В версии 0.6.4 администраторы и владельцы Telegram-чата исключаются всегда; оставьте `excludeChatAdministrators: true`.

## Причина отклонения регистрации

- При отклонении регистрации доступны **Указать причину**, **Отклонить без причины** и **Отмена**.
- Причина вводится в личном чате модератора, ограничена 1 000 символами и сохраняется как комментарий решения в одной транзакции с переходом в `REJECTED`.
- Заявитель получает локализованное сообщение с причиной. Telegram отправляет её как обычный текст, поэтому ввод модератора не интерпретируется как Markdown или HTML.
- Аудит хранит числовой ID модератора, ID заявки, время перехода и признак наличия комментария, но не дублирует полный текст.
- Условный переход гарантирует успех только первого допустимого действия модератора. Устаревшее действие не может дописать причину после завершения заявки.

## Точные ошибки авторизации

Wire-протокол остаётся версии `1`, но клиент и сервер 0.6.4 показывают отдельные сообщения на русском и английском:

- `ACCOUNT_NOT_FOUND`: подключившийся ник отсутствует в локальном синхронизированном кэше, включая визуально похожие, но разные имена.
- `ACCOUNT_NOT_SYNCHRONIZED`: используется только при настоящем нарушении состояния синхронизации.
- `ACCOUNT_DISABLED`: игровой профиль заблокирован.
- `INVALID_CREDENTIALS`: proof не совпал; сведения о verifier/HMAC не раскрываются.
- `CREDENTIAL_OUTDATED`: надёжно обнаружено несовпадение версии учётных данных после смены пароля.
- `AUTH_TIMEOUT`: авторизация не завершилась за отведённое время.
- `INVALID_CHALLENGE`, `REPLAY_DETECTED` и `INVALID_SESSION`: одно безопасное сообщение о невозможности подтвердить авторизацию.
- `PROTOCOL_MISMATCH`: версии клиента и сервера несовместимы.
- `INTERNAL_AUTH_ERROR`: безопасное общее сообщение без stack trace, ошибок БД, URL, токенов, verifier и proof-данных.

## Диагностика `RESYNC_PLAYER`

Типизированная команда версии 1 теперь возвращает структурированные причины: `ACCOUNT_NOT_FOUND`, `MINECRAFT_NAME_MISMATCH`, `BACKEND_UNAVAILABLE`, `SYNC_EVENT_NOT_FOUND`, `ACCOUNT_DISABLED` или `INTERNAL_ERROR`, когда применимо. Несовпадение подключённого ника определяется через UUID кэшированного аккаунта; безопасный результат содержит `accountId`, `registeredMinecraftName`, `connectedMinecraftName` и `reason=MINECRAFT_NAME_MISMATCH`. Учётные данные и verifier не возвращаются.

## Совместимость

| Компонент | Требование 0.6.4 |
| --- | --- |
| Схема БД | `7`; требуется автоматическая миграция |
| Wire-протокол авторизации | `1`; без изменений |
| Обновление backend | Обязательно |
| Обновление серверного мода | Обязательно для новой классификации ошибок и диагностики `RESYNC_PLAYER` |
| Обновление клиентского мода | Обязательно для всех новых локализованных сообщений об отключении |

Сначала разверните backend, затем замените оба Minecraft-мода до повторного открытия сервера. Уже синхронизированные аккаунты сохраняют возможность входа при временной недоступности backend, но смешивание версий 0.6.3 и 0.6.4 не даёт полного поведения 0.6.4.

См. [руководство по переходу с 0.6.3 на 0.6.4](MIGRATION_0.6.3_TO_0.6.4_RU.md).
