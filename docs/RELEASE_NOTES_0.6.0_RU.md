# MCTGAuth 0.6.0

[English version](RELEASE_NOTES_0.6.0.md)

## Главное

- В Telegram появились раздел «Информация о сервере», статус, список игроков и «Моё время на сервере».
- Dedicated server отправляет авторизованную телеметрию и фиксирует сессии без входящих подключений.
- Для модераторов добавлены раздел «Обращения», постраничная статистика игроков и отдельная блокировка Telegram-бота.
- Миграция `V005` повышает схему базы до `5`; полный reset включает состояние телеметрии.

## Telegram UX

- Выдаваемый ботом пароль отображается как Telegram HTML `<code>` только для самого значения; окружающий текст остаётся обычным, пароль не журналируется.
- Как играть, необязательные Скачать сборку и Веб-карта, а также Статус сервера находятся в разделе «Информация о сервере». Необязательные ссылки управляются конфигурацией.
- Статус использует timeout свежести 60 секунд по умолчанию. При устаревшем heartbeat сервер считается недоступным, старые счётчики и списки не показываются как текущие.
- Список игроков показывает только активные сессии и их текущую длительность при свежей телеметрии.
- «Моё время» позволяет выбрать принадлежащий пользователю аккаунт и показывает рассчитанные backend итоги за последние 24 часа, 7 дней и всё время, включая активную сессию без двойного учёта перекрытий.

## Администрирование и модерация

- Обращения сгруппированы в разделах: новые, мои, в работе, регистрации, нарушения, проблемы, статистика и поиск.
- Статистика игроков — отдельный экран с проверкой права и постраничной выдачей общего времени и online/last-seen состояния.
- «Заблокировать пользователя в боте» и «Разблокировать пользователя в боте» требуют подтверждения, используют числовые Telegram ID и создают идемпотентные записи аудита. Блокировка бота не отключает Minecraft-аккаунты.
- Назначение, ответы, решения, paging/search, enable/disable аккаунтов и удалённое управление остаются отдельными рабочими потоками.

## Телеметрия

- При каждом запуске создаётся новый `serverInstanceId`; сервер отправляет авторизованные исходящие POST на `/api/v1/servers/heartbeat`, `/api/v1/servers/player-events` и `/api/v1/servers/shutdown`.
- Heartbeat по умолчанию каждые 20 секунд. События игроков атомарно журналируются в `mctgauth/telemetry-events.json`, отправляются по порядку фоновым worker, повторяются с ограниченной задержкой и ограничены 10 000 событиями.
- `PLAYER_JOINED` и `PLAYER_LEFT` используют стабильные ID событий и авторитетный ID Minecraft-аккаунта; ник хранится как снимок для отображения.
- Новый instance закрывает старые сессии с причиной `SERVER_LOST` по последнему достоверному heartbeat. Штатная остановка использует `SERVER_SHUTDOWN`, если событие доставлено.
- HTTP телеметрии не выполняется на tick, login, logout или render thread Minecraft.

## База и операции

- `V005__telemetry_and_bot_blocking.sql` добавляет `users.bot_blocked`, `server_status`, `player_sessions` и `telemetry_events`.
- Full reset очищает таблицы телеметрии и локальный журнал, сохраняя миграции и требуемую конфигурацию модераторов.
- Уже синхронизированные аккаунты продолжают работать при недоступности backend; сбой телеметрии не отключает локальную авторизацию.

## Совместимость и конфигурация

- Wire-протокол авторизации: версия `1` (без изменений).
- Локальный кэш авторизации Minecraft: schema `1` (без изменений).
- Конфиг сервера: `[telemetry] enabled`, `heartbeatIntervalSeconds` (по умолчанию `20`) и `maxQueuedPlayerEvents` (по умолчанию `10000`).
- Telegram YAML: `serverStatus.enabled`, `heartbeatTimeoutSeconds` (по умолчанию `60`), `showPlayerCount`, `showPlayerList`, `showSessionDuration`.
- Телеметрия использует существующие server ID и Bearer-токен длиной не менее 32 символов. В production требуется HTTPS; заголовки Authorization не журналируются.

См. [руководство перехода с 0.5.0](MIGRATION_0.5.0_TO_0.6.0_RU.md) и [API телеметрии](api/TELEMETRY_API_RU.md). Документ описывает реализованный набор функций и не утверждает успешность конкретного deployment или запуска тестов.
