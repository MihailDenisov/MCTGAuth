# Переход с MCTGAuth 0.6.3 на 0.6.4

[English version](MIGRATION_0.6.3_TO_0.6.4.md)

Версия 0.6.4 требует согласованного обновления backend, серверного мода и клиентского мода. Wire-протокол авторизации остаётся версии `1`, но база backend мигрирует со схемы `6` на `7`, сервер различает дополнительные причины отказа и возвращает структурированную диагностику `RESYNC_PLAYER`, а клиент содержит их локализованные сообщения.

## 1. Подготовка и резервная копия

Остановите новые административные операции, зафиксируйте текущий release и создайте проверенный SQLite backup:

```bash
sudo /opt/minecraft-auth-tools/status.sh
sudo /opt/minecraft-auth-tools/backup.sh
```

Также сохраните `/etc/minecraft-auth.env` и `/etc/minecraft-auth-telegram.yaml`. Никогда не помещайте их секреты в release-архив.

## 2. Настройка необязательных тегов участников

По умолчанию теги выключены. Для включения отредактируйте существующий файл из `TELEGRAM_FEATURE_CONFIG_PATH` (обычно `/etc/minecraft-auth-telegram.yaml`) и добавьте:

```yaml
memberTags:
  enabled: true
  chatId: <TELEGRAM_GROUP_CHAT_ID>
  excludeChatAdministrators: true
```

Укажите числовой ID ровно одной целевой группы или супергруппы. Не используйте группу модераторов/администраторов неявно, если только она намеренно не выбрана тем же явным `chatId`. Бот должен использовать Telegram Bot API 9.5 или новее, быть администратором этого чата и иметь право `can_manage_tags`.

Версия 0.6.4 никогда не назначает игровой тег администратору или владельцу Telegram-чата; оставьте `excludeChatAdministrators: true`. Права модератора MCTGAuth не связаны с ролью пользователя в Telegram-чате.

Если при `enabled: true` нет допустимого `chatId`, backend безопасно отключает теги и пишет предупреждение без секретов. По умолчанию у пользователей выбран вариант **Без тега**. Сохранение настройки не требует текущего членства и не откатывается при недоступности Telegram. Для сверки используются обновления о вступлении в чат и административное действие **Синхронизировать теги чата**, защищённое отдельным permission.

## 3. Обновление backend

Загрузите и активируйте backend 0.6.4 обычным управляемым updater:

```bash
sudo /opt/minecraft-auth-tools/update.sh \
  /home/authbot/uploads/auth-backend-0.6.4.tar.gz
```

При запуске применяется `V007__chat_tags_and_registration_rejection.sql`. Миграция добавляет nullable-поле `users.chat_tag_account_id` со ссылкой на `minecraft_accounts(id)` и `ON DELETE SET NULL`, а также расширяет сохранённые pending-действия модераторов для причин отклонения регистрации. Для существующих пользователей остаётся вариант «Без тега».

Проверьте:

```bash
sudo /opt/minecraft-auth-tools/health.sh
sudo /opt/minecraft-auth-tools/logs.sh -n 200
sqlite3 /var/lib/minecraft-auth/auth-backend.db \
  "SELECT version, name FROM schema_migrations ORDER BY version;"
```

Ожидаемые значения `/version`: приложение `0.6.4`, схема `7`. В логах не должно быть bot/API-токенов, заголовков авторизации, паролей, verifier или proof-данных.

Deployment-toolkit блокирует откат только приложения к release, максимальная схема которого ниже 7. Если нужен настоящий откат данных, восстанавливайте согласованный backup до обновления только штатной подтверждаемой процедурой restore.

## 4. Обновление Minecraft-сервера и клиентов

Остановите Minecraft, замените серверный JAR на `mctgauth-server-0.6.4.jar` и запустите сервер после успешной проверки backend. До открытия сервера раздайте всем игрокам `mctgauth-client-0.6.4.jar`.

Версия протокола остаётся `1`; сброс учётных данных или локального кэша аккаунтов не требуется. Тем не менее оба мода нужно обновить для полного набора точных сообщений об отключении. Серверный мод 0.6.4 также нужен для UUID-проверки и результата `MINECRAFT_NAME_MISMATCH` команды `RESYNC_PLAYER`.

## 5. Проверка поведения

- В личном чате бота откройте **Настройки → Тег чата**. Должны отображаться только включённые профили этого пользователя и **Без тега**.
- Сохраните «Без тега» и выбор профиля. Оба действия должны завершаться успешно, даже если пользователь временно не состоит в целевом чате.
- Проверьте, что обычный участник получает актуальный ник аккаунта, а администратор/владелец чата не получает игровой тег.
- Имитируйте контролируемую ошибку Telegram: настройка в БД должна сохраниться. После восстановления доступа запустите **Синхронизировать теги чата** модератором с permission `telegram.member_tags.sync`.
- Отклоните одну регистрацию с причиной, другую без неё. Заявитель должен увидеть причину только в первом случае, а устаревшее действие второго модератора должно быть отклонено.
- Проверьте локализованные сообщения для неизвестного ника, отключённого аккаунта, неверного пароля, устаревшей версии учётных данных, timeout, несовместимого протокола и безопасных ошибок проверки/внутренней системы.
- Выполните `RESYNC_PLAYER` для известного аккаунта. Если подключённый UUID соответствует другому имени, структурированный ответ должен содержать только ID аккаунта, зарегистрированное имя, подключённое имя и причину `MINECRAFT_NAME_MISMATCH`.

Не сбрасывайте игровые сессии или данные авторизации при этом обновлении.
