# MCTGAuth 0.6.5

[English version](RELEASE_NOTES_0.6.5.md)

MCTGAuth 0.6.5 добавляет приватное распознавание устройств и управляемые модератором блокировки. Устройство — связь many-to-many: один пользователь может использовать несколько устройств, а одним устройством могут законно пользоваться несколько людей. Совпадение служит только основанием для проверки, не доказывает тождество людей и никогда само не создаёт блокировку.

Клиент собирает только включённые идентификаторы после MCTGAuth-handshake и в рабочем потоке авторизации. Сильные сигналы (`SYSTEM_UUID`, `MACHINE_ID`, `MOTHERBOARD_UUID`, `DISK_ID`) включены по умолчанию. Слабые `GPU` и `MAC_ADDRESS` выключены и при выключении не запрашиваются. Значения нормализуются и хешируются SHA-256 локально; исходные значения не передаются и не журналируются. Backend применяет HMAC-SHA-256 с отдельным секретом `DEVICE_FINGERPRINT_SECRET` и хранит только эти ключевые токены.

Resolver использует централизованные веса и требует совпадения хотя бы одного сильного сигнала. Стабильные сильные сигналы сохраняют устройство при замене диска; слабые совпадения сами по себе не разрешают устройство и не расширяют связанную блокировку. Для связей устройство↔пользователь и устройство↔аккаунт сохраняются first/last seen и счётчики входов.

Модератор может просмотреть влияние, заблокировать только пользователя, явно включить пользователей с общими напрямую наблюдавшимися устройствами, заблокировать устройство, снять отдельную или всю связанную группу блокировок и управлять исключениями общего ПК. Распространение строго одношаговое и нерекурсивное. Явная блокировка устройства не отменяется linked-ban-исключением. После снятия запись остаётся неактивной в истории, а обычный `enabled` аккаунта независим от блокировки.

Известные блокировки пользователей и устройств синхронизируются в локальный кэш сервера и действуют при недоступности backend. Неизвестное устройство по умолчанию допускается при сбое backend, чтобы сохранить офлайн-вход из валидного кэша; строгий режим включается параметром `deviceFingerprint.failClosedWhenBackendUnavailable`.

Автоматическая очистка наблюдений отложена в 0.6.5. Документированный срок хранения — 365 дней; нельзя удалять данные активных блокировок, исключений и аудита.

Требуется согласованное обновление: приложение `0.6.5`, протокол `2` (клиенты 0.6.4 отклоняются), схема backend `8`, fingerprint version `1`.

См. [руководство перехода с 0.6.4 на 0.6.5](MIGRATION_0.6.4_TO_0.6.5_RU.md).
