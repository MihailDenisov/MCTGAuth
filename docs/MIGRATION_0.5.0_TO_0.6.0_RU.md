# Переход с MCTGAuth 0.5.0 на 0.6.0

[English version](MIGRATION_0.5.0_TO_0.6.0.md)

## Обзор

0.6.0 устанавливается поверх 0.5.0. Версия wire-протокола авторизации остаётся `1`, формат локального кэша Minecraft — schema `1`. Миграция backend повышает схему базы с `4` до `5` и добавляет телеметрию, сессии игроков и состояние блокировки Telegram-бота.

Обычное обновление сохраняет пользователей, Minecraft-аккаунты, учётные данные, обращения и возможность входа уже синхронизированных игроков. Запланируйте перезапуск backend и Minecraft-сервера. Установите согласованные JAR 0.6.0; после замены клиентского JAR игрокам нужно перезапустить клиент.

## 1. Резервная копия

```bash
sudo /opt/minecraft-auth-tools/backup.sh
sudo cp -a /etc/minecraft-auth.env /etc/minecraft-auth.env.pre-0.6.0
sudo cp -a /etc/minecraft-auth-telegram.yaml /etc/minecraft-auth-telegram.yaml.pre-0.6.0
sudo systemctl stop minecraft.service
sudo tar -C <MINECRAFT_GAME_DIR> -czf /var/backups/minecraft-auth/mctgauth-pre-0.6.0.tar.gz mctgauth
```

Используйте фактические имя systemd-сервиса и абсолютный `MINECRAFT_GAME_DIR`, если они отличаются.

## 2. Конфигурация телеметрии и статуса

Серверный мод использует существующие идентификатор сервера и токен:

```toml
[backend]
baseUrl = "https://auth.example.com"
serverId = "survival-main"
apiToken = "<тот же токен длиной не менее 32 символов, что и AUTH_API_TOKEN>"

[telemetry]
enabled = true
heartbeatIntervalSeconds = 20
maxQueuedPlayerEvents = 10000
```

`MCTGAUTH_API_TOKEN` может переопределять `backend.apiToken`. Токен и файл конфига являются секретами. В production требуется HTTPS; входящий порт Minecraft не нужен. При `telemetry.enabled=false` телеметрия выключена.

В существующий `/etc/minecraft-auth-telegram.yaml` добавьте или объедините:

```yaml
serverStatus:
  enabled: true
  heartbeatTimeoutSeconds: 60
  showPlayerCount: true
  showPlayerList: true
  showSessionDuration: true
```

Timeout ограничен 10–3600 секундами и по умолчанию равен 60. Сохраните остальные настройки и `TELEGRAM_FEATURE_CONFIG_PATH`; не заменяйте env-файл целиком и не меняйте секреты.

## 3. Установка и миграция

```bash
sudo /opt/minecraft-auth-tools/update.sh /path/to/auth-backend-0.6.0.tar.gz
sudo /opt/minecraft-auth-tools/status.sh
```

При запуске транзакционно выполняется `V005__telemetry_and_bot_blocking.sql`, после чего запись появляется в `schema_migrations`. Добавляются `users.bot_blocked`, `server_status`, `player_sessions` и `telemetry_events`; существующие данные сохраняются, история телеметрии начинается пустой.

Установите `mctgauth-server-0.6.0.jar` только на dedicated server, а `mctgauth-client-0.6.0.jar` — только игрокам.

## 4. Телеметрия и статус

Сервер отправляет авторизованные исходящие POST-запросы: `/api/v1/servers/heartbeat` (по умолчанию каждые 20 секунд), `/api/v1/servers/player-events` для `PLAYER_JOINED`/`PLAYER_LEFT` и `/api/v1/servers/shutdown` при штатной остановке, если это возможно.

Каждый процесс получает новый `serverInstanceId`. События имеют стабильный `eventId`, авторитетный `minecraftAccountId` и снимок ника. Игровой callback только фиксирует данные; один фоновый worker атомарно хранит события в `mctgauth/telemetry-events.json`, отправляет их по порядку и повторяет с ограниченной задержкой. Лимит журнала по умолчанию — 10 000 событий. После перезапуска неотправленные события сохраняются; полный reset удаляет журнал.

Backend принимает только настроенный `serverId` с общим Bearer-токеном. Свежий heartbeat определяет online. Устаревший или остановленный сервер считается недоступным, старые счётчики и списки не показываются как текущие. Новый instance закрывает старые сессии по последнему достоверному heartbeat с причиной `SERVER_LOST`; недоказуемое время после него не учитывается.

## 5. Изменения Telegram

В меню зарегистрированного пользователя появился раздел **Информация о сервере**: Как играть, необязательные Скачать сборку и Веб-карта, Статус сервера и Назад. В **Мой аккаунт** добавлено **Моё время на сервере**; при нескольких аккаунтах сначала выбирается принадлежащий пользователю аккаунт. Backend считает последние 24 часа, последние 7 дней и всё время по временным сессиям, объединяя перекрытия.

В `/adm` обращения сгруппированы в **Обращения**. **Статистика игроков** — отдельный разрешённый и постраничный экран. Администратор может с подтверждением блокировать и разблокировать доступ Telegram-пользователя к боту по числовому Telegram ID. Это не отключает Minecraft-аккаунты: `enabled` меняется отдельным действием.

Выдаваемый пароль отображается как HTML `<code>` только для самого значения пароля. Правила генерации и обработки секретов не меняются; пароль не журналируется и не попадает в аудит.

## 6. Проверка и откат

После обновления проверьте `/health`, `/version`, schema `5`, логи миграции и доставку тестового heartbeat. Проверьте `/menu` и `/adm` на русском и английском, status/player list/playtime, разделы Requests и block/unblock с тестовыми аккаунтами.

Миграция не запускается на backend 0.5.0: он поддерживает schema `4`, а после обновления становится `5`. Откат приложения выполняйте только по защите deployment-инструментов; для возврата базы остановите сервисы и восстановите проверенную копию до обновления, затем установите согласованные артефакты 0.5.0. Не восстанавливайте только одну сторону.

## Полный сброс

Инструмент reset теперь очищает `server_status`, `player_sessions`, `telemetry_events` и `telemetry-events.json`, сохраняя миграции и требуемую конфигурацию модераторов. Полный сброс удаляет историю времени и требует повторной регистрации всех пользователей; это разрушительная операция, а не шаг обычного обновления.
